## 2. 已确认的 2.4.5 播放变化

### 2.1 播放器内核

- 主程序仍包含 `KSAVPlayer`、`KSMPVPlayer`、AVFoundation、VideoToolbox、FFmpeg/libav 和 Metal 相关能力。
- 内嵌 mpv 源码标记从 `libmpv-v0.40.0` 变为 `libmpv-v0.41.0`。
- `KSAVPlayer` 的字段从 2.4.0 的 `urlAsset` 变为 `io`。通过 2.4.5 的 Swift 符号类型可确认：

  ```text
  KSPlayer.KSAVPlayer.io : KSPlayer.Either<Foundation.URL, AVAsset>
  ```

  这说明 2.4.5 的 AVPlayer 路径可以在 URL 与 AVAsset 两种输入之间抽象切换；结合新增的缓存/预加载类型，播放器与业务自定义 IO 的结合更紧密。

### 2.2 缓存与预加载

2.4.5 新增真实 Swift 类：

```text
LimitSeparatePreLoadIOContext
  ├─ maxFileSize
  ├─ maxReadedFileSize
  ├─ loadMoreBuffer
  ├─ fakeUrlPos
  ├─ moreDownload
  └─ moreUrlPos
```

同时发生以下结构变化：

| 类型 | 2.4.0 | 2.4.5 | 解释 |
|---|---:|---:|---|
| `CacheIOContext` 字段数 | 14 | 15 | 新增 `bytesRead`，保留逻辑位置、Range seek 偏移、EOF 和下载状态 |
| `ReadCacheIOContext` 字段数 | 7 | 4 | 重构为 `tmpURL`、`end`、`logicalPos`、`entryCache` |
| `DSVideoKsPlayerViewController` 字段数 | 52 | 59 | 新增缩略图进度、系列/同步状态、本地路径、媒体源和计时器等字段 |
| `KSAVPlayer` 字段数 | 28 | 27 | `urlAsset`/`startPlayTime` 等字段变化，新增 `io` |

2.4.5 还出现：

- `isRangeUncached(start:end:)`
- `performSeek(time:flags:)`
- `preferredRange` / `setPreferredRange:`
- `bufferMiss`
- `maxBufferCount`
- `maxBufferSize`
- `clearBufferWhenStopped`
- `preloadAllFrames`

这些证据支持 2.4.5 对 Range 缺口检测、seek 前后缓存判断、首选 Range、缓冲未命中和播放器缓冲容量做了更明确的建模。具体 Range 窗口大小和阈值仍需要真机网络日志确认。

定向 Ghidra 交叉引用进一步显示：`preferredRange`、`setPreferredRange:`、`bufferMiss`、`maxBufferCount`、`maxBufferSize` 和 `clearBufferWhenStopped` 均落在实际访问器/函数引用中；`CacheIOContext`、`ReadCacheIOContext` 的日志/类型字符串也有实际函数落点。`isRangeUncached(start:end:)` 和 `performSeek(time:flags:)` 已确认存在于 2.4.5 播放模块字符串中，但当前部分分析没有解析出调用者，因此仍标记为“实现线索”，不把它们直接当作已确认运行时调用路径。

### 2.3 播放控制器新增能力

2.4.5 的 `DSVideoKsPlayerViewController` 仍保留：

- `cacheNextIOContext`
- `isPreloadVideo`
- `enablePreLoadNext`
- `isLive`
- `isTransCode`
- 音轨/字幕索引
- `mediaSources`
- `progressTimer` / `reportTimer`

新增或明显出现的字段包括：

- `videoThumbnailInfo`
- `thumbLeftConstraint`
- `progressThumbEnable`
- `seriesModel`
- `isSyncTrakt`
- `localPath`
- `file`、`movieFile`、建议文件集合
- 缩略图和内容视图的延迟存储对象

这说明 2.4.5 的拖动体验可能加入了进度缩略图/预览和更细的进度上报计时，而不仅是播放器内核版本升级。

### 2.4 媒体源和请求

2.4.5 继续保留 2.4.0 的：

- `PlaybackInfo`
- `MediaSourceInfo`
- `MediaStream`
- `DirectPlay` / `DirectStream` / `Transcode`
- `supportsDirectPlay` / `supportsDirectStream` / `supportsTranscoding`
- `directStreamUrl` / `transcodingUrl`
- `AudioStreamIndex` / `SubtitleStreamIndex`
- `PlaybackPositionTicks`
- `playSessionId`

2.4.5 新增一条更具体的请求模板：

```text
/PlaybackInfo?AutoOpenLiveStream=true&IsPlayback=true&UserId=
```

这提示 2.4.5 可能对“真正进入播放”的 PlaybackInfo 请求增加了显式播放标志和用户上下文。是否所有播放入口都走此模板，必须由 2.4.5 真机抓包确认。

定向交叉引用还命中了 `handlePlaybackStateChange` 和 `updatePlaybackProgress` 的实际函数引用，说明播放状态变化与进度更新不是只有字符串/方法名残留；但调用频率、上报条件和失败重试仍需真机日志验证。

### 2.5 转码和字幕

2.4.5 新增：

- `BSFTranscodeContext`
- `MetalSubtitleView.swift`
- `SubtitleRightView.swift`
- `VideoSubtitleView.swift`
- `subtitleDelay`

2.4.0 已存在音频、视频、字幕转码 context，因此 2.4.5 更像是在既有转码链路上增加 bitstream-filter 适配和 Metal 字幕渲染/布局能力，而不是完全更换转码架构。

## 4. 当前结论与待验证项

当前最有价值的版本差异不是“2.4.5 播放器更快”这一主观判断，而是它把自定义 IO、Range 缺口、seek、缓冲容量和进度缩略图建模得更明显。对 Nastart 最值得验证的假设是：

1. 2.4.5 是否在拖动前调用 `isRangeUncached`，并根据缺口触发独立预加载。
2. `LimitSeparatePreLoadIOContext` 是否服务于下一视频预加载，还是服务于当前视频的独立 seek 预读。
3. `KSAVPlayer.io` 的 `URL` 分支和 `AVAsset` 分支分别对应哪些媒体源/缓存条件。
4. `preferredRange`、`maxBufferCount` 和 `maxBufferSize` 的实际值及触发时机。
5. 新的 `PlaybackInfo` 请求模板是否改变了服务端返回的媒体源或首帧耗时。
6. 进度缩略图是否通过额外 Range 请求读取关键帧/缩略图资源。

这些问题需要在同一视频、同一账号和相同网络条件下，对 2.4.5 真机记录 HTTP 请求、Range、首帧、seek 恢复和内存轨迹。IPA 静态分析不能替代这些运行时证据。

## 5. 单独脱壳主程序核对结果

因此这不是一个比 IPA 内主程序更完整或不同的第二份样本，对当前静态逆向没有额外增益。它仍可作为后续真机运行时定位时的来源确认，但不能单独提供调用栈、实际 Range 请求、缓冲参数取值或播放时序证据；这些仍需真机动态观测和网络/性能日志验证。
