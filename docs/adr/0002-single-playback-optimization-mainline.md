# ADR 0002：集中优化新播放架构，旧架构仅作回退

日期：2026-09-06

状态：已接受（用户明确决定）。本决策补充 ADR 0001，并取代其中独立重建播放控件、长期并行探索多条架构的执行方式。

## 决策

Nastart 视频播放唯一持续优化主线是 **Greenfield 新架构**，以 **KSPlayer 原始流优先** 为主要优化链路。旧架构保留的目的只是新架构出现问题时能够回退，以及关键里程碑的必要对照；不再作为并行功能建设或性能优化主线。

“Force original KSPlayer”不是第三种架构，而是新架构内部的选流策略。常规播放入口只提供一个“播放架构”选择器，选项为“新架构 / 旧架构”，不再暴露强制原画开关。新设置默认新架构；用户主动选择的旧架构持久保存，各入口共用同一设置。历史强制原画偏好不再读取，不允许形成不可见的第三种模式。

新架构使用自动选流策略：优先适合当前媒体与网络的原始流；认证代理、直连、HLS/AVPlayer 是同一架构内的传输或兼容分支，不是独立架构选项。原始流优先不等于无条件强制原始流。不要为了缩减选项删除必要的认证、网络或格式兼容处理。

播放 UI、手势、设置、音字幕选项等尽量共用已有实现。架构优化不授权重做界面或删减原有功能。HLS 等兼容分支也必须保持基本功能完整，但当前不与 KSPlayer 原始流主线同时开展同等深度的性能优化。

## 执行原则

- 后续开发、问题定位和正式验收矩阵集中于新架构；旧架构只做回退可用性和关键里程碑对照，不在每次小改动后重复整套新旧矩阵。
- DS One、Lenna 用于回答明确的功能或性能问题；不因竞品研究重新铺开架构选择。
- 测试综合首帧、连续播放、暂停恢复、seek、音字幕、画质切换、PiP、退出续播、内存和传输证据。截图只是视觉证据，时钟推进不是显示合成器首帧测量。
- 覆盖 iPhone/iPad、设备文件/Jellyfin，以及内网 Wi-Fi、外网 Wi-Fi、外网蜂窝网络。当前 NAS 外网不可用，只执行局域网；缺失条件保留未验证，不据局域网通过宣称全网通过。
- 本次入口变更沿用现有 DEBUG 迁移范围，尚未将 Release 默认播放路径切换为未完整验收的新实现。架构方向已确定，Release 切换属于验收后的迁移工作。

## 旧架构退出条件

新架构基本功能完整，既定真机矩阵与关键格式/网络条件取得足够证据，已知阻塞缺陷关闭，性能和稳定性达到验收要求后，迁移正式入口至新架构，并删除旧架构专属代码、设置与仅由旧架构使用的依赖。保留新架构仍使用的共用 UI 和兼容引擎。

最终产品只保留一个优化后的播放架构，架构选择器随旧架构一起移除。不能仅凭少数样本能播放、首帧更快或截图正常就提前删除回退路径。

## 当前实施

Jellyfin、设备文件、直接链接入口共用 `PlaybackArchitecturePicker`，沿用同一个持久化架构偏好；强制原画 UI 与偏好读取已移除。更低层的原始流策略模型暂留作内部实现，不由常规播放入口强制启用。
