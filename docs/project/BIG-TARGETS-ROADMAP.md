# Nastart 大目标总纲

**日期**：2026-11-21
**定稿人**：用户 + Muse
**用途**：指导大目标一个接一个的实现顺序。每个大目标先拆成小件，一件一件交接给实现方（Codex），不一次全给。Muse 负责定目标、写交接、真机验收；Codex 只负责实现交接里写明的代码。

## 做法（已定）

- 一次只做一个大目标；一个大目标拆成小件，一件一交接。
- 每件交接只含实现方要实现的代码：改哪些文件、做到什么、怎么验收。不写实现方猜得到的笼统目标。
- 实现方每件必须自己编过、跑过相关测试再交回，不交“看着对但没编过”的代码。
- Muse 验收不过的，把失败证据写回交接打回重改。

## 说明

- **Cloud 同步的生产容器暂缓**：生产 CloudKit 容器需苹果付费开发者计划（$99/年；CloudKit 本身免费）。先做本地部分（同步引擎、数据模型、冲突/删除、电视端、状态 UI、本地模拟测试），容器启用与真机跨设备实测等付费计划到位后再做。
- **SMB 越根是 blocker，不是大目标**：第 04 节开口项，挡住 SMB 生产接入。应在相关大目标推进时顺手清掉，不单独占一个大目标位置。
- **第 04 节其余开口项**（密码输入根因、在线资料来源未选定、家庭外 Wi-Fi 与听音、预检五类失败）同样随大目标推进时逐个关闭，不单独立项。
- **顺序可调**：3 号之后的顺序是建议，用户可随时调整；1、2 号已定（Cloud 同步 → Agent）。

## 每件交接的固定格式

1. 背景（一句话：这件解决什么）。
2. 改哪些文件（精确到文件与函数）。
3. 做到什么（数据模型、行为、边界）。
4. 不做什么（明确排除，避免漫延）。
5. 测试与验收（实现方自己跑过的测试 + Muse 真机验收标准）。
