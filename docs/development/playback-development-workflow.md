## 2. 先明确规则，再选择媒体

每个问题先关联 PX/UX 编号，定位到以下层次；不能仅以片名作为根因分类：

| 层次 | 应先验证的共用规则 | 典型任务 |
| --- | --- | --- |
| 会话与异步任务 | stop 终止会话；资源至多释放一次；旧任务不能覆盖新会话/账号；上报与取消顺序明确 | PX-21、PX-20 |
| 时间与用户意图 | 区分请求 seek 与已确认位置；暂停不被切轨取消；HLS 映射保留绝对内容位置 | PX-02、PX-20、PX-21 |
| 选流与传输 | 同一网络快照；预算与格式依据一致；有限 Range、连续响应、取消与重试有界 | PX-01、PX-03 |
| 解复用/解码与输出 | 正确轨道和生命周期；音频可听；字幕内容正确；HDR 输出证据独立 | PX-20、PX-07～PX-11、PX-18～PX-19 |
| 展示与产品操作 | 入口/菜单与真实状态一致；加载、网页退出及导航可恢复 | UX-01～UX-04、PX-05～PX-06、PX-12～PX-17 |

优先用可控制返回顺序、取消时点和失败注入的测试固定规则；无需真实电影才能复现的逻辑，不反复靠电影手测。合成 fixture 要注明模拟的协议/格式和局限，不能替代真实解码、屏幕及听音验收。只针对有依据的共用缺陷修改，不重建架构、不按片名/文件路径添加特殊参数。

## 3. 四层验证及触发条件

| 层级 | 何时执行 | 最小范围 | 能形成的结论 |
| --- | --- | --- | --- |
| L0 逻辑/离线 | 每次相关源码修改 | 相关确定性回归、preflight；Swift 编译/XCTest 在 Mac | 规则覆盖与代码验证；不能标真机通过 |
| L1 定向真机 | 一个修复达到可构建状态 | 原失败操作 + 同技术特征另一片源；共同播放路径改动至少 S01 四单元和受影响路径 | 修复在声明范围内有效，未覆盖项保留 |
| L2 代表性回归 | 每批结束；共享传输/解码/会话等高影响改动在合并前 | 下方影响映射中的格式族；iPhone/iPad、设备文件/Jellyfin；相关双设备专项 | 可结束本批开发，不能推算全矩阵通过率 |
| L3 完整矩阵 | 候选里程碑/发布构建、默认架构迁移、删除旧回退前；或发现广泛回归 | 原 19×4、实际可达网络、ISO/电视剧及双设备独立专项 | 对具体构建/环境形成正式验收 |

L1/L2 可按影响范围选样本，不受“必须先完成 S01 全部未来功能才能测试 S03”的限制。原失败仍阻止该修复验收，不能为改善通过率绕过失败。L3 保留正式顺序及发现问题先修复回归的纪律；环境不可达/工具缺失单列，不无限重试，也不记通过。

传输窗口/超时/重试/解码模式修改继续满足旧规范硬门槛：Range/fixture 检查、S01 双设备与 S03/S08/S11/S18 格式族回归。分层不能降低这项门槛。未知影响范围按高影响处理。

## 4. 从现有样本中选代表集

先复用已冻结样本，核对实际轨道/容器/文件版本后使用。表内技术特征来自现有记录，尚缺的探测字段仍待补，文件名不能证明 DV/Atmos 实际输出。

| 样本 | 已记录的覆盖特征 | 使用位置 |
| --- | --- | --- |
| S01 哈尔 | 小容量 MKV、H.264；已有 seek/HLS 内容映射证据 | 基础播放与双入口基线 |
| S03 碟中谍3 | 大 REMUX、HEVC、TrueHD、多音轨/ASS | 索引/传输、无损音轨和文本字幕 |
| S08 黑豹2 | MP4、HEVC、HDR、双音轨 | 不同容器与 HDR 路线 |
| S11 神奇动物 | MKV、HEVC 10-bit、TrueHD、多音轨 | 无损音轨交叉验证 |
| S18 方世玉2 | H.264、FLAC、双音轨、不同目录 | 另一音频格式与文件入口 |
| S19 指环王1 | 128.8 GB、长时长、TrueHD/DTS/AC3、PGS | 压力、位图字幕、深位置；不作为所有功能唯一样本 |

前五项是共享链路回归骨架；S19 在涉及大偏移、深位置、PGS 或压力时加入，以及 L3 必测。按缺口加入 S02（LPCM）、S05（交错扫描）、S10（1080p HEVC 10-bit）；不为凑数量扩表。ISO、TV01～TV03、外置字幕继续独立专项；PGS、DV 各 profile 或 Atmos 某输出缺第二样本时明确“缺覆盖”，可以增加有来源的 fixture/样本，但不得假称现有样本覆盖。

| 改动范围 | L1/L2 选择与必要操作 |
| --- | --- |
| 停止/取消/断点/账号隔离 | S01 四单元、S03 两入口；加入 S19 深位置及 MTP-01～03 相关退出/重开场景；重复 stop、旧响应、从头播放 |
| Range/缓存/解码器共用逻辑 | S01/S03/S08/S11/S18 四单元；S01 串行及并发；大偏移改动加 S19；原画与实际可用 HLS 分列 |
| 音轨/字幕 | 基础 S01 四单元及改动覆盖格式：S03 ASS、S19 PGS、S11 TrueHD、S18 FLAC；外置字幕单列；切换→暂停→seek→退出组合与实际 SUB/AUD |
| 选流/首帧 | S01/S03/S08 四单元，必要时 S19；两入口同轨同点配对，明确原画/HLS、冷/热；路由测试不依赖隐藏清晰度菜单 |
| PiP/HDR/杜比 | 受影响普通 SDR 与已核实 HDR/杜比样本，两设备；全屏→后台→恢复→关闭；格式识别、真实输出分列 |
| 剧集/章节/片头片尾/字幕搜索/投屏 | TV01～03 或具有实际章节/字幕的样本；接收端另列；切集、失败恢复及状态保留 |
| 网页/列表/排序等纯非播放变更 | UX fixture 与两设备相关页面；触及播放器呈现/退出生命周期再加 S01 四单元，纯文档无需播放回归 |

## 5. 一次修复的闭环与停止条件

动手前在当轮交接记录填写下列变更卡；证据不足先补观测，不能开始试参数：

```text
问题/关联编号：
基线 commit + 工作区差异标识、构建、设备/网络：
复现步骤、实际/期望行为：
根因假设与支持证据；尚未排除的解释：
影响的共用规则、入口、引擎及格式族：
技术路线/开发状态/测试矩阵受影响段落；是否仅改变观测口径：
最小修改与确定性反例：
L0/L1/L2 清单；本次是否触发 L3：
成功条件、非退化条件、测量口径和性能预算：
实际结果/失败/证据；未执行项及原因：
结论的适用范围；下一步及回退点：
文档同步结果；已接受实现与已撤回实验是否区分：
```

2026-10-19 维护补充：每批获得新实现、测试结果、失败/回退、设备安装/阻塞或用户约束时，及时更新开发状态、当前交接与PROGRESS的相应内容；需求编号状态仍只在总账维护。链路改动同时更新技术路线的实际接受实现、流程图、源码映射和核对日期；回退后路线也恢复，不把失败实验留作当前方案。风险覆盖变化更新正式矩阵当前执行版，历史结果保留。无相关变化时核对即可，不复制流水或制造进展；纯文档修改无需播放回归，也不产生新包。收尾运行文档路径检查与差异格式检查。

正确性修复以反例被阻止、相关不变量成立、必要回归无新增失败为退出条件；崩溃须完成原复现/压力场景及诊断核实，不能仅凭一次没崩溃关闭。第一批 NAS 修改的 4 项新增 XCTest 尚未运行，不属于已验收基线。

性能工作在测量前固定目标、重复次数与非退化预算，不事后挑口径：每个可比条件至少 3 次探索性重复，报告中位数、范围、失败数；3 次不算可靠 P95。超过预算的慢样本保留并归因，不能从统计中删除。首帧屏幕证据、播放时钟和 renderer submission 分列。已有 30 秒连续播放、t=3/10/30s 与代表样本 10 分钟稳定性要求保留。

当前尚无经验证的统一“全部影片 N 秒出帧”预算。下一批先建立正常构建的代表集基线，逐路线固定预算，再进行性能修改；预算未定时只报告观测，不能以“变快了”验收性能目标。对照必须同片/同轨/同字幕/同点/同网络/同构建条件，跨提交比较记录准确版本，ASan 数据排除在性能比较之外。

同一假设连续两轮受控修改未带来预期变化，停止追加参数，记录否定证据，转向下一层观测或缩小复现。L0/L1/L2 满足变更卡后结束该修复，不因“还能再快一点”继续扩展；新问题另建关联记录。尚缺 Mac/真机的工作交付为待验证，不冒充完成，也不因缺条件删除需求。

## 6. 下一阶段如何承接全部目标

| 原批次 | 本流程下的推进门槛与产物 | 原任务 |
| --- | --- | --- |
| 1：基础播放 | 先会话/事件/位置规则与崩溃证据，再代表集基线与分阶段性能；每个修复有变更卡和影响回归 | PX-01～PX-04、PX-20～PX-21 |
| 2：PiP | 建立在稳定会话与暂停/恢复上；验证完整往返、HDR 字幕与输出 | PX-05～PX-07 |
| 3：字幕/选集 | 复用最后选择、取消与状态隔离规则；文本/位图/外置及 TV 专项分别验 | PX-08～PX-12 |
| 4：内容功能 | 真实章节/片头片尾区间/字幕源，验证 seek 与失败恢复 | PX-13～PX-16 |
| 5：投屏/杜比 | 独立接收端及输出证据，格式识别不冒充实际支持；核验可提前但不抢占批次 1 | PX-17～PX-19 |
| 补充体验 | 页面/fixture 验证可独立推进，涉及呈现生命周期时纳入播放回归 | UX-01～UX-04 |

批次 1 达到已声明的正确性与性能门槛后，推进批次 2；暂缓的 PX-04 和有明确外部条件的剩余项带原因保留，不要求隐藏入口完成验收才能推进。未解释的退出崩溃、错误断点或跨会话污染属于基础阻塞，不能被某个首帧成绩掩盖。正式发布/架构迁移仍须 L3，不能以日常代表集替代。

立即执行顺序：

1. NAS：以现有生命周期分析为入口，补停止上报顺序、旧会话/账号响应隔离的确定性证据和回归设计；审查本地未编译改动。产物是有限的逻辑修复及变更卡，不继续围绕 S19 调参。
2. NAS：整理现有代表样本缺失的规格字段、日志必需字段与配对条件；先核对 Swift 真实策略再修改离线工具，Auto/Force 历史比较不能冒充设备文件/Jellyfin 比较。
3. Mac：编译与 XCTest；验证本批退出/取消/旧详情反例，完成 ASan 崩溃捕获；随后正常包执行 L1/L2 并补代表集基线。性能测量不能先于正确性阻塞的处理。
4. 交接：更新唯一总账的证据与下一步、记录当前构建和工作区状态；只修改实际验证单元。历史通过保留为历史，不复制为新构建通过；受影响单元在当轮回归记录中明确待重测。
