## 修正两个具体诊断/状态缺陷

`ObservingPlaybackIOContext` 仅观察 renderer 所持有的实际 I/O，此前 preload 不读取数据却标记缓存，read 返回空 Data 并报告网络来源，导致4MiB预算瞬间被写成预加载完成。现在不伪造缓存或数据：不支持的 read 明确报错，preload 保持观察适配器职责。`PreloadCoordinator.schedule` 限制实际范围、返回经缓存验证的完成字节，并在失败/取消时清理活动任务。会话诊断分开 requestedBytes 与 preloadedBytes，未物化记 bytesNotMaterialized/实际0，不再报告假完成。

Launchpad 增加分类路由探测的开始/结束/跳过、候选数、选中地址类型/协议/端口、耗时及播放 trace 关联，便于区分“尚未探测”与“已验证同服务器LAN”。未修改实际选路、网络窗口或缓冲策略；没有新增原始 URL/凭据公开字段。

三个真实反例在旧实现3/3失败；修正后105项 PlaybackNextCoreTests 全通过，0失败/0跳过。正例使用实际物化 fixture bytes 验证预算与缓存，不能用观察适配器假成功。设备正常构建、15项 preflight 和 diff 检查通过。历史4MiB preloadCompleted 是预算/意图日志，**不是已读取缓存字节证据**；历史日志保持原样但不得继续据此推论预取已完成。
