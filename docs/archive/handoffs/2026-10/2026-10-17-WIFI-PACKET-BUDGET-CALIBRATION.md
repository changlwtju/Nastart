## 修正与失败保留

旧 Instruments 连接计数漏掉实际媒体传输，不能继续作为预算依据。本轮改读 pcapd 原始包，不按 App PID 筛选，物理 en/pdp_ip 双向 IP 长度计入，包含 UDP、重传和 ACK；lo/utun 不重复计算，不等同运营商账单。

捕获库原 watch 路径会把 protocol_family 的 vlan 标记强转枚举而中断；部分 en 包 frame_pre_length=0 却已有以太网头，再补头导致 ARP 误当 IP；VLAN 内非 IP EtherType 亦曾触发错误。已依据私有原始坏帧修正，从原始 struct 按真实链路头解析；非 IP 帧按 EtherType 排除，未知/截断 IP 与不支持的格式仍失败即停，未静默忽略媒体错误。基础工具见 scripts/device_packet_budget.py，18 项定向 Python 单测通过。首次 Python3.9 联合类型注解不兼容、早期枚举/包头/VLAN 失败样本均保留，未丢弃失败后只报成功。

普通媒体 URL 表单的键盘/旋转使自动化起止边界不可靠，Return 后实际下载曾已开始而后续按钮守卫失败；未判为 App 性能故障。本轮按运行手册配置例外，使用现有 DEBUG playbackLab URL/greenfield 环境键，在同一普通 Debug 包内播放本机已知大小 MP4。该例外仅用于计量与主动终止，结束已恢复环境/参数均空，不能混入普通播放性能基线。测试片是有意生成的噪声图，不是媒体解码花屏证据。

- 限额例：4 MiB 阈值实际观测 4,194,752 IP bytes，阈值到终止返回 **0.068 秒**；停止并继续捕获 3 秒后共 **4,746,419 IP bytes**，相对预算多 **552,115 bytes**。目标 TCP 响应 4,522,247，服务端成功写正文 4,521,984。服务端写前预留计数 4,538,368 包含一次未成功写出的块，不能把预留数当成功正文。解析错误 0，最大捕获延迟约 1.006 秒。终止均核对当前 App PID 后有意执行，非自然崩溃，非正常退出验收。

**边界：**这是一次约 2 MB/s 的本地 HTTP/1.1 校准，尚未证明 Jellyfin TLS/h2/QUIC、大文件并发/Range、高速突发及蜂窝物理链路覆盖。约 1 秒捕获延迟在高速下会产生更大余量，不能保证严格上限。IPv6 普通长度计入，扩展头暂不做目标 TCP 分类，jumbogram 明确失败即停。预算信号与独立终止目前是私有受控工具；公开模块只是计量原语，不能单独作为蜂窝保护器。旧 retry calibration-required 标记仍在，未解锁旧蜂窝脚本。
