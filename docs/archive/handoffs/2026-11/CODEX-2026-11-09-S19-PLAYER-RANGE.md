# 2026-11-09 S19 起播等待分段：索引与正文

接续 [S19 同落点同轨实机和分段供给](CODEX-2026-11-09-S19-MATCHED-SMB-AND-RANGE.md)。目标是在实际播放器上区分“尾部索引没有收到”和“定位后的媒体正文供给不足”。旧 iPad 设备文件黑屏保留，未借本批判定其原因。

## 隔离方法

- 在独立 A16 iPad 模拟器运行 Debug，Mac 的 loopback 提供 24 秒 H.264 MP4，23,442,110 字节。视频由本机生成，4,476 字节的 MP4 索引放在尾部。各窗都用同一文件、同一 14 秒起点、App 的有限 Range 原流代理和实际 KSPlayer 渲染表面。每窗挂载后约 3.5 秒主动关闭，不等待到产品默认超时。
- 先用无故障窗确认实际请求偏移，再只对 23,437,634（尾部索引）或 8,795,705（定位后的正文）注入。将源站日志、代理同一 transferID、同一 trace / plan 的引擎事件逐项核对。没有用真实影片、NAS 或手机流量。
- 首次构建复用副本中的绝对模块缓存，编译停止且没有播放器请求；改用新构建目录后五个有效窗完成。该夹具由隔离测试宿主直接挂载渲染器，未通过真实目录或普通全屏退出路径。引擎阶段相对引擎准备时刻，内部时钟相对宿主挂载；两条时间线不能直接相减，均非显示器首帧。

| 窗口 | 代理和引擎实际观察 | 挂载到内部时钟推进 |
| --- | --- | ---: |
| 正常供给 | 索引 206、26 ms 到响应头，定位返回 0，首帧提交 | 775 ms |
| 索引响应延迟 5.5 秒 | 客户端先关闭，代理未收到该段响应头；定位未开始，无首包、接受帧或提交记录 | 截止未推进 |
| 定位后正文限速 64 kbps | 2 ms 收到 206 头；定位返回 0，有首个视频包，但截止没有接受帧或提交记录 | 截止未推进 |
| 索引响应延迟 640 ms | 索引 640 ms 到响应头并交付完整 4,476 字节；打开阶段约 693 ms，定位及提交随后发生 | 1,170 ms |
| 定位后正文限速 10.8 Mbps | 1 ms 收到 206 头，定位及提交成立；代理采到仍在流入的正文，起播无需等到该 Range 全部交付 | 1,166 ms |

“首个视频包”是本次引擎已观察到的首包，不能认定来自目标位置。定位返回成功也不代表已呈现。两种供给故障都能在无时钟推进时留下不同阶段的退场记录；减轻故障的两窗都继续起播。每种条件仅一窗，合成 MP4 与 S19 的 Matroska、音轨、字幕、真实链路不同。未调整缓冲目标、重试、代理策略或正式播放代码。

## 工具与收尾

- 播放诊断报告新增 `incompleteEngineStartups`：只采纳同时匹配 trace 和 plan 的退场事件，缺失阶段为未知；未推进不会被当作起播成功，避免混入速度配对。146 项播放脚本测试通过。
- 模拟器和 loopback 服务已停止，测试实例已删除。临时测试宿主源码逐字节恢复，498 个 iOS 输入与 `807b3c7e…` 签名真机包的冻结清单一致；本轮未启动、覆盖或改动 iPad、iPhone 13、iPhone 18、Apple TV。iPad/13 的最近实测状态见 [真机记录](CODEX-2026-11-09-S19-MATCHED-SMB-AND-RANGE.md)，不把模拟器结果当真机。
