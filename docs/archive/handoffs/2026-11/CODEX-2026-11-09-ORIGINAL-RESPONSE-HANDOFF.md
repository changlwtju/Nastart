# 2026-11-09 原流首个 Range 响应接手

接续 [iPad 的 32 KiB 独立预读对照](CODEX-2026-11-09-IPAD-ASYNC-PREFIX-AB.md)。此前准备和播放分别发请求，首次正式 GET 到达时预读尚未完成，实际交付 0。此前 [13 和 iPad 的原流审计](CODEX-2026-11-09-ORIGINAL-VALIDATOR-AUDIT.md) 还发现两机 Jellyfin 的 206 都无 ETag。这一批改为提前启动正式的首个有限 Range，匹配的播放器读取接手同一条上游任务。

## 接手规则

- `DevicesView.swift` 的 `AuthenticatedMediaStreamProxy.prepareOriginalResponse` 仅受理已登记、尚未读取的有限 HTTP(S) 原流能力。提前发出的 `bytes=0-33554431` 与普通首个从零读的上游 Range 相同。首个无条件、无查询参数、从零开始且无末端的同路由 GET 接手该任务及已有响应头、正文；HEAD 不接手，有效但不匹配的 GET 取消准备后照常读取。
- 等待接手仅保留一个槽，最多 2 秒。代理正文缓冲到 64 KiB 可暂停上游，在接手前硬限 256 KiB；这个限额不描述 URLSession 或 TCP 自身缓冲。路由撤销、监听失效或超时取消，首个准备窗不参与自适应速率估计。
- 首窗始终来自同一响应，不依赖 ETag。已接手的连续读取后续窗核 URL 与总长度，有强 ETag 时也核对标识并发送 `If-Range`。无版本标识时不能检出同 URL、同大小的源内容替换。HLS、网络媒体库本地桥接、允许自签的路由（含实际为 HTTP 的 13 设备文件路由）本批不接手。
- `PlaybackSessionCoordinator.prepare` 在共同选路后调用可选回调。`GreenfieldVideoPlayerModel` 仅在 iOS Debug 初始启动显式设 `NASTART_ORIGINAL_RESPONSE_PROBE=1`，且实测普通 Wi‑Fi、私网地址、从头、KSPlayer/原流代理/direct play 时发起。正常启动不发起，Release 无此开关。回调不等待响应；`ObservingPlaybackIOContext` 的实际字节仍为 0，代理接手与实际发送各自记录。

## 本机验证

源码为 main/8db1cc64 加继承的未提交修改及本批新增 diff，Xcode 27.2 / iOS 27.0 新建空白 iPhone Air 模拟器。首轮 17 项有 1 项断言失败：合成 H.264 的首段成功接手并交付，之后 KSPlayer 另发偏移 44 和回到偏移 0 的读取，不能以整个解码窗口只准一条 GET 判断首段是否重复。修正断言核首次正文交付前的唯一请求，保留失败日志。

最终同源 17 项代理、解码及兼容回归通过，另 3 项共用准备入口定向通过。32 KiB 夹具在头前与头后接手均收到完整等值正文且各只发一次上游 GET；512 KiB 节流夹具在 65,536 字节暂停并恢复同一响应。无 ETag 的合成 H.264 实际解码并到达候选对齐。撤销/过期、条件及非零读取、总长或强 ETag 改变均覆盖。共用准备测试覆盖 Jellyfin 与设备文件正例，默认关闭、续播、受限路径、无实测快照反例，并复核三入口共同网络策略与本地文件。临时模拟器已删除。

准备就绪、实际发送、内部首帧和真实显示是不同证据。未用本机合成数据判断 NAS、真机显示、真实听音或播放速度。结果和下次配对条件见 [结构化结果](../../../testing/results/2026-11/CODEX-ORIGINAL-RESPONSE-HANDOFF-20261109.json)。

## 接续判定

保留 iOS Debug 显式入口，暂不默认开启。在同机同入口交替顺序重复，核播放器接手前后的源端请求数、实际字节、失败回退、显示首帧、相同续播落点和跳转；续播当前刻意不启用。自签 HTTPS 仍需要复用已有固定信任传输或独立证明等价，不能为接手放宽证书。网络存储去桥接单独推进：`NetworkMediaByteReader` 保持在 NetworkMedia 包，App 的共享代理路由持有 Reader 能力，共用现有 Range 解析、背压和撤销；校验、认证与协议读仍归 Reader。优先用夹具核有限范围、同 Reader 的生命周期和取消，再串行回归 WebDAV / SMB / FTP；FTP 与 SMB 限内网。之后分真实内网、外网和弱蜂窝校验同网络环境的入口一致性，不由本窗推断长时、听音或 NAS 负载。
