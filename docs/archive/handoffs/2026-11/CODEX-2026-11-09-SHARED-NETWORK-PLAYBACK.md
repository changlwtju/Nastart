# 2026-11-09 同网络环境的播放接续

用户要求在 Jellyfin、设备文件和网络存储入口同步优化大文件体验，覆盖断点续播、从头播放、音轨字幕切换和快进回退。同一实际网络环境共用播放规划，协议承担字节供给及认证、文件版本校验。FTP、SMB 的实测保持内网。

当前产品源码基线为 `main/8db1cc64`，之前的 2.5 秒跳转缓冲试验已回退。已接受的第一步共享代理仍通过本机桥接读取网络存储。直接 Reader 路由、FTP 控制连接复用、可消费预读仍待后续。当前批由 Codex 单写，修改范围为 `LaunchpadPlaybackCore.swift`、`PlaybackIntent.swift`、`GreenfieldVideoPlayerView.swift` 和 `PlaybackNextCoreTests.swift`。

本批修正共同准备步骤的网络输入。原先桥接以服务器地址推断网络，昂贵网络和受限标志固定 false。现在共同准备步骤获取既有 `PlaybackNetworkObserver` 的同一份默认设备路径快照，再把连接地址私网属性与原有 estimatedBitrate 输入保留到规划器。首次路径回调使用 150 ms 等待预算（调度延迟另计），支持取消，回调尚未到达则保留已有输入并记录证据未就绪。真实本地文件及合成 loopback 来源继续使用其原有上下文。诊断标明 `devicePathSnapshot`、路径代次和两个标志，快照描述设备默认路径，具体媒体任务的实际端点与接口仍需同窗核对。tvOS 的独立来源适配及播放中切网后的重新规划仍待接续。

| 网络维度 | 三入口共同验收条件 |
| --- | --- |
| 内网 Wi-Fi | 同一大文件及音字幕条件，先核来源、总字节和实际路线，逐台安装新包后串行执行 |
| 公网 Wi-Fi | 保留保存域名及实际请求端点，分别记录原流或转码和媒体条件 |
| 蜂窝、低数据模式或昂贵网络 | 使用共同路径快照及共同规划，先核默认路径和实际媒体接口，沿既有字节计量与 Wi-Fi 收尾规则执行 |

每个入口依次检查从头播放、正常退出后的续播、音轨选择、字幕选择及关闭、前后 15 秒和中段定位。记录真实请求时间、恢复时钟、实际截图、选择状态和普通退出。内部 `first_frame` 的播放时钟证据与实际屏幕首次显示分列，音轨派发时间与实际听音恢复分列。格式与实际路线不同时分别报告，失败和超时保留。
