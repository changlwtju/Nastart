# 播放器设置的共用服务清单行

日期：2026-11-01。承接[共用外观选项](2026-11-01-SHARED-APPEARANCE-CARD-OPTIONS.md)，继续不依赖 NAS 的三端设置细节。本批未发现、控制或安装真机，未请求 NAS、读取真实凭据、播放或写源目录；既定模型分工与 NAS/VPN/签名配置保持。

## 接受的实现

手机/Pad 和 TV 的播放器设置现用同一 `NastartPlayerIntegrationRows` 和服务顺序，沿既有四项 Jellyfin、Emby、Plex、Navidrome，没有增加协议、原生服务或播放器入口。名称复用 NetworkMedia 的 `MediaServiceProduct`，图标和顺序只定义一次；暖色图标、主次文字、可换行状态及辅助字号纵排共用，TV 保留宿主主题卡片和分隔，移动保留 Form。

新增纯展示状态 `NastartPlayerServiceState`，区分清单在线/安装/异常/停止/未知、尚未确认、已发现线索和已保存独立授权。移动保留原有“服务名包含匹配、取首个状态”的来源，仅把 online 等译成“清单显示在线”等措辞；没有匹配时用“尚未确认”，不据此推断没安装或未授权。TV 保留原有名称/详情匹配及 Jellyfin 已保存授权优先，否则显示已发现线索或尚未确认；没有把清单线索当作接口或登录验证。

两端都给 Emby/Plex/Navidrome 加“原生媒体库尚未接入”说明，并共用“服务清单与登录授权分别管理”的页脚。移除手机原行的在线状态点，以明确的清单文字表达来源。Jellyfin 的真实授权仍由宿主独立管理；移动此页不新增读取 Keychain、验证会话或保存授权的能力。

组件只接收展示状态闭包，不创建 model、客户端、账户或 Task。TV 原 discoverServices 任务及其后续源码字节未变，数据层、认证、服务身份校验、请求路线和播放链路保持。现有名称包含匹配可能有重名/多实例误判，本批没有修复或扩大该识别逻辑；精确服务身份仍由网络媒体服务页负责。

## 离线预览与未验范围

既有 `--offline-ui player-settings` 及 settings 的播放器目的地增加同一四行，用合成固定状态覆盖保存授权、尚未确认、清单停止和已安装；不读取实际库存、凭据或服务，不发起发现或状态跳转。它只扩充既有播放器设置预览，未增加场景枚举或参数，不代表完整正式页、外部播放器发现或真实登录验收。

TV 模拟器 Debug 构建完成后，现场可用空间约 3.55GiB，低于 TV 3.8GiB 和移动 6GiB 门槛。准备脚本及 runner 的预算断言都在创建设备前退出，原始退出记录保留；0 新模拟器、0 安装启动、0 截图或偏好访问，不定性为 App 崩溃。没有降低预算、清用户缓存/旧包或继续盲试。字体、长状态换行、大字/英文、完整列表、焦点/读屏均未做本批 UI 验收，不复用前批外观截图冒充本批画面。

## 来源与构建

HEAD `4de732dd645b36671becff992cdef1d0163fd1e4`，446 输入，5 个既有文件变化：AppTheme、MineView、TVNASViews、两种语言资源；其余 441 个 hash 一致。每语言新增 10 个相同键，原有键值保持，plutil 检查通过；旧资源和全部其他未提交修改保留。源码前后、完整脏树、构建命令/时间、包路径与二进制 hash 仅在本机私有证据区，指针 `current-shared-player-service-rows-private`。

复核到手动服务清单也可标为 online，已将初始“运行中”改为更准确的“清单显示在线”，不推断进程健康；初始源码与构建记录单独保留，无UI证据。最终源码只完成 TV 模拟器 Debug；移动模拟器重建时从约2.03GiB触及2GiB保留线，自有进程组被主动终止，exit -15。其余移动Debug/Release与TV无签名Debug/Release未按最终措辞重建，不能沿用中间六配置成功。结果见[结构化结果](../../../testing/results/2026-11/2026-11-01-shared-player-service-inventory-rows.json)。剩余构建启用 2GiB 保留线监测及自有进程组退出清理，不为构建清理用户资料。本批展示变更未新增镜像单元或 UI 测试，没有重跑旧参数、服务或遥控用例；编译不等于排版、真实服务或 Release 体验验收。

本批未冻结新候选；根包清单保留上批外观源码的30核签移动候选，但明确标记与当前源不匹配，不能用于最新包回归。当前源清单已更新，包的原源码身份保留并另记当前不匹配原因；TV 正常签名沿旧 profile 阻塞，不重试，保留的 444 输入/27 Mach-O 旧签名包仍不匹配当前源码。测试包与普通包的身份分别记录，不把无签名编译当正常签名或真机安装成功。
