# 2026-11-09 Apple TV：配对页开启后的现场验证

21:51–21:55 用户确认电视停在“设置 → 遥控器与设备 → 远程 App 与设备”。沿用当前以太网与配对记录；以有线 IPv4、同一 Bonjour 主机和上一轮记录的硬件身份核目标。未发起 PIN 配对、未重启或安装，也未更改路由、VPN、NAS 或设备配置。原始网络和设备标识只留本机私有证据区。

| 检查 | 结果 |
| --- | --- |
| Device Hub 27.2 | Apple TV 出现在“配对附近设备”的电视列表，选中后只有 Next 配对路径；普通设备列表无该电视。已关闭本次发现窗口。 |
| 电视的局域网服务 | 现场收到 AirPlay、常规 RemotePairing 和手动配对 Bonjour 广播，均核同一有线主机。三个服务的实际广告 TCP 端口在该主机的 IPv4 和两个 IPv6 地址均能连接。传统 `_apple-mobdev2` 广播端口则均超时，与开发隧道用途未建立关联。浏览窗口内未找到匹配电视的 `_remoted` 广播。 |
| Mac 开发设备服务 | `devicectl list devices` 无电视，按真实硬件标识的详情返回未找到。原生 `remotepairingd` 的服务枚举返回三个其他设备，对该硬件的定点发现也没有提供可用端点。仅在找到该端点时才会请求开发隧道，这次没有执行该请求，也没有发配对命令。 |
| 同窗日志 | 配对广播识别到电视。未见指向该电视的开发隧道请求或新 1005。Mac 当前没有定向抓包权限，不能把日志没有请求等同于已用网络抓包证明没有数据包。所有自有观察进程已结束。 |

结论：基础发现和配对服务正常应答，故障在建立开发连接之前已经可以复现：Mac 服务没有把电视作为可申请开发隧道的设备提供出来。现有证据无法确定是电视没提供开发端点，还是 Mac 没接纳它。下一次先核电视自身是否显示配对后应有的“开发者”设置；如果能得到独立 Mac，再保持同网做宿主对照。只有出现可用设备端点后才继续追踪隧道请求、响应与签名安装。 [前次无线与有线认证证据](CODEX-2026-11-09-APPLE-TV-WIFI-WIRED-PAIRING.md) · [Apple 对 tvOS 开发者设置的说明](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device?changes=_8)
