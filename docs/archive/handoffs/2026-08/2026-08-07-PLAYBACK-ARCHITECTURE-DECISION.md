# Nastart 播放链路原则

## 决策

Nastart 使用“一套播放会话、两个引擎、两个来源适配器”：

- 设备文件：认证后的 DSM 原始 Range URL → MobileVLCKit。
- Jellyfin：先通过 PlaybackInfo 获取原始直播放流 → 同一个 MobileVLCKit 播放会话。
- Jellyfin 卡顿或用户主动降画质：请求 Jellyfin HLS 转码资源 → 仍复用同一套控制层和播放状态。
- AVPlayer 只作为 HLS/MP4 等系统兼容资源的系统能力引擎，主要服务 PiP、AirPlay 和系统级后台播放；不作为 MKV、ISO、PGS、TrueHD 原始文件的默认引擎。

## 产品行为

默认原画优先，不针对单个片源预设码率。原始流没有在 watchdog 内出画面、提前结束或明确报错时，播放器自动执行一次兼容替换：Jellyfin 以当前时间点协商低延迟 H.264/AAC HLS，DSM 设备视频以同一 Range URL 切到软件解码。替换继承当前位置、倍速、音轨、字幕和方向；替换请求本身不再携带替换入口，因此不会形成无限重试。界面保留原画与明确清晰度选项，用户仍可随时切回原画。

直播放流的字幕/音轨在 VLC 内切换，不重建会话；HLS 质量或服务端音轨切换需要重新请求转码资源，必须带上当前时间、倍速、音轨和字幕状态，因此不能承诺与原始文件同样的毫秒级响应。

## 不承诺的边界

- DSM 没有转码能力；软件解码只能解决本机解码兼容性，不能解决蜂窝或公网带宽不足。此类情况应切换外部播放器，或通过 Jellyfin 兼容流播放。
- ISO9660 主标题可支持；UDF-only、Blu-ray 菜单和完整光盘导航需要外部播放器或服务端 remux。
- PiP 不是 VLC 原始渲染层的天然能力；进入 PiP 前需准备 AVPlayer 兼容 HLS。
