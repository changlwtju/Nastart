## 执行顺序与证据

1. 每轮先现场重核设备、连接和最新包身份。iPhone13优先使用实际蜂窝上游、Wi-Fi关闭和已验证SlowNetwork3G弱网条件，记录下行/上行、延迟/丢包及实际公网协议/端口；正常蜂窝另列基线。iPad按实际网络能力记录，热点或Wi-Fi限速不能标成该设备直接蜂窝。
2. 对同一NAS、同一文件版本，分别从设备文件和Jellyfin入口启动，核对容量/完整长度、时长、编码、轨道及实际源流。Jellyfin自动HLS与设备文件原流分开列组；按各入口实际支持能力验证弱网回退，缺能力记产品缺口。禁止按片名硬编码。
3. 分开计时：点击→准备、清单/索引、服务端首片、内部首帧、实际可辨画面；采持续播放与缓冲、断流恢复/重试、远距离及暂停中seek、暂停恢复、深位置退出续播、字幕/音轨实际生效、正常退出和稳定性。首轮短段后补至少一段十分钟观察，保留失败、超时、未知和工具失效。
4. 大文件必核大于4GiB偏移、完整长度、Range续段/短EOF及内存/Jetsam；不要用小文件、首帧成功或稀疏截图替代。声音、精确字幕/落点及完整显示流畅度按真实证据独立判定。
5. 同步优化两入口共用播放/传输/缓存/续播/字幕音轨逻辑，并分别处理设备文件Range与Jellyfin清单/转码/候选接手问题。每次公共链路修改都重建核验并对两入口定向回归；一入口通过不代表另一入口通过。真机串行执行，记录NAS负载，不并发压测。
6. 结束恢复最新普通包、测试条件关闭和原无线状态，更新交接/进度及独立入口结果。竞品按现有矩阵另做共同条件配对，未达资格不排名。
