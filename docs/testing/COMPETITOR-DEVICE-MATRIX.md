## 公平性与分层

- **同协议受控对照**：同物理设备、同服务/账号权限、同文件版本/大小、同路径/协议、同音轨/字幕、同起点、同画质与直放/转码状态；记录 NAS 负载、LAN/公网/蜂窝/VPN、设备温度/低电量/屏幕刷新率、音频路由。
- **默认体验对照**：保留各 App 默认策略，单独报告是否预取、转码或选择不同媒体源，以及达到的画质/声音/字幕能力。默认更低码率不可直接称为原画更快。
- 从详情页点击到首帧是核心端到端指标；App 启动到详情页另测。首帧不得用 Nastart 独有内部日志与竞品屏幕画面混比。
- 区分进程冷启动、热重开、媒体数据冷/热缓存、NAS/服务端缓存。杀进程不等于缓存清空；无法证实的缓存字段填 unknown 并停止严格性能聚合，允许定性观察。不要为测试破坏用户缓存/下载。
- 使用相同录屏/采样方案、相同起止事件和时间基准。若工具改变系统动画、采样开销、App 优化级别，记录并保持配对一致；未优化 Debug 与 App Store 包不能给出公平性能胜负。
- 单路播放、顺序配对，采用 ABBA 或交替顺序；每个设备/入口/素材/缓存条件至少 5 个有效配对，保留失败与超时。报告原始值、成功率、p50、最大值及配对差值；不足 20 次不将 p95 当作稳定统计。超时不填 0、不丢弃失败后只比较成功样本。
- 先以 S01 等低负载代表样本建立路线，再按需加入 HEVC/4K、ASS/PGS、不同音频格式、ISO、电视剧。继续遵守现有 NAS 负载限制：不运行大电影人为限速转码，不并发压测 NAS。

## 自动化判定与证据

1. 自动化脚本必须保存包身份、目标页面、动作时刻、前/中/后界面证据、采样覆盖时间和数据完整性。手势 API 成功不等于滚动发生，也不等于流畅。
2. 当前滚动工程门槛：每页至少 12 次有效滑动、覆盖至少 10 秒，前台确为被测 App，采样完整；前台合成显示 hitch 时间不超过 5 ms/s，且没有单次 ≥100 ms hitch。这是一项项目验收门槛，不冒充用户永远感受不到卡顿。多表/多图层重叠的 hitch 应合并区间，防止累计重复。
3. 必须有实际内容位移证据，不能把短页边界回弹记作长列表滚动通过。无数据、权限不足、帧证据采样率不足、未覆盖动作时段均判 INSUFFICIENT/TOOL，不能判 PASS。自动工具额外要求 display-vsyncs-interval 在每次拖动中至少 30 个显示计时样本/秒、首尾及相邻样本间隙不超过 50 ms（60 Hz 设备的保守完整性门槛）；空 hitch 表不能替代该证据。vsync 属于合成显示计时，不能解释为 App 实际渲染 FPS；门槛不满足时保留原始间隙，不能仅凭此区分掉采样与真实卡滞。
4. 首帧/字幕可自动分析录屏并复核原始帧。以最后未达成帧、第一达成帧给出时间区间；30 fps 视频不报毫秒级精度。WDA 截图轮询延迟较大时只提供上下界，不与高精度内部时钟直接排名。
5. 音轨实际生效需要音频或可验证的听测证据；无法采集时自动判定“证据不足”，不能用选中态伪造通过。字幕选择同理需真实 cue。
6. 自动输出 PASS / FAIL / INSUFFICIENT，区分功能正确性与相对速度；任何明显功能错误先判失败，不因速度更快抵消。新版本重跑相同配对，不复用旧 App 测量值。
7. 竞品不支持的功能标 N/A，未配置/无订阅/未登录为 BLOCKED，未测 U；均说明原因。历史 DS One 动态画面可用于导航参考，不能作为本轮新包公平排名。
